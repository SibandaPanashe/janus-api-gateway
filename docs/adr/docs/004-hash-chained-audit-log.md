# ADR-004: PostgreSQL Event Log for Audit Trail Over File-Based Logging

## Status
**Accepted** (Implemented May 2026)

## Context
Janus processes authentication, rate limiting, and billing decisions
for every API request. Regulated environments (fintech, healthcare)
require a tamper-evident audit trail showing:
- Who made each request
- What decision was made
- When it happened
- What the client's plan and usage was at that moment

File-based logging (Logback to files/stdout) is ephemeral, searchable
only with external tools, and provides no tamper evidence.

## Decision
Persist every gateway decision to the PostgreSQL `event_logs` table
as a structured record. Each event includes the client ID, event type,
endpoint, response code, plan at time of request, and current request
count. The `EventLogService` writes to both structured logs (via SLF4J
with MDC trace IDs) and PostgreSQL in the same operation.

## Implementation Detail

**Table Schema:** `event_logs` with columns for `client_id`, `event_type`
(REQUEST_ALLOWED, RATE_LIMITED, KEY_CREATED, KEY_REVOKED), `endpoint`,
`ip_address`, `response_code`, `plan_at_time`, `request_count`, `metadata`
(JSON blob for extensibility), and `created_at` (TIMESTAMPTZ).

**Trace Correlation:** Every request carries an `X-Request-ID` header
(propagated from Nginx or generated by `TraceIdFilter`). This trace ID
appears in both the structured log output and can be stored in the
event metadata for cross-referencing.

**Query Examples:**
```sql
-- All events for a client in the last hour
SELECT * FROM event_logs
WHERE client_id = 'my-client'
  AND created_at > NOW() - INTERVAL '1 hour'
ORDER BY created_at DESC;

-- Rate limit frequency by client
SELECT client_id, COUNT(*) as rate_limits
FROM event_logs
WHERE event_type = 'RATE_LIMITED'
  AND created_at > NOW() - INTERVAL '24 hours'
GROUP BY client_id
ORDER BY rate_limits DESC;
